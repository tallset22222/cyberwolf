# Cyberwolf character standard, part 1: skeleton (v0.1 draft, for review)

Machine-readable source: `skeleton.json` (generated by `build_spec.py`; the tables below are generated from it).
Diagram: `skeleton_overview.png`.

The skeleton is **designed independently for Cyberwolf**. It borrows general practice (layers, twist joints,
attachment frames, separate face rig) but no names, hierarchy or data from any other game's rig.

## Conventions

| item | rule |
|---|---|
| units / axes | metres; +Y up; character faces +Z; character's left is +X (glTF convention) |
| rest (bind) pose | A-pose: upper arms 45° below horizontal, legs straight, feet under the hips |
| reference profile | `bio_reference`, stature 1.75 m. Other profiles move joints, never rename or re-parent them |
| joint frame | local +Y points from the joint to its primary child; local X is the main flexion axis; twist is about local Y |
| naming | snake_case; side suffix `_l` / `_r`; prefixes `hlp_` (helper), `sock_` (socket), `ext_` (chassis extension, reserved) |
| hierarchy | parents listed before children; one root (`root`) at the ground |

## Layers

| layer | count | animated? | skin weights? | purpose |
|---|---|---|---|---|
| core | 61 | yes, keyed | yes | the retargeting contract: every animation targets these names |
| twist | 14 | no, driven from core | yes | spread forearm, upper-arm, thigh and calf twist along the segment |
| helper | 16 | no, procedural | yes | anatomical deformation (volume preservation, creases); secondary-motion targets |
| socket | 29 | no, rigid | **never** | attachment frames for rigid cyberware, held items, optics |
| ext (reserved) | 0 | chassis graph only | chassis parts only | chassis-specific joints (pistons, plates) parented under core joints; ignored by retargeting |

The layers mirror what the REDengine research showed works well: animation, procedural anatomy, and secondary
motion kept as separate layers. The face is a **separate rig component** bound to `head`, specified later; the base
skeleton carries only `head`, `jaw` and the two eyes.

## Full-borg and augmented bodies

- **Profiles.** A chassis is a proportion profile: the same joints at different positions.
  - Heavy chassis: longer limbs, a wider stance.
  - Ordinary characters: the biological profiles.
  - Animation retargets by joint name; nothing is renamed or removed.
- **Unweighted core joints.** A chassis may leave core joints without skin weights (a solid torso shell needs no
  `spine_02` deformation), but it must keep them in the hierarchy.
- **Extra joints.** Moving hardware gets `ext_` joints under the nearest core joint, animated by the chassis' own
  graph. Ordinary animation never touches them.
- **Sockets move with the profile.** A heavy chassis' `sock_shoulder_l` sits where its shoulder is, so the same
  shoulder pod fits both bodies (scaled, if the item allows it).

## Open points for review

1. Finger detail: 3 phalanges per finger plus ring/pinky metacarpals (17 per hand). Drop to 2 per finger for a lower-cost variant?
2. One toe joint (`ball`) per foot. Separate big toe for bare-foot characters?
3. `neck_01` / `neck_02` give two neck joints, so head and neck replacements can cut at `neck_mid` or `neck_base`.
4. Helper placement is anatomical intent only; their drivers (the deformation graph) come with the base mesh.
